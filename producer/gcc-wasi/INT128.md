# GCC signed and unsigned int128

Patch `0009-int128.patch` enables the public C/C++ `__int128`,
`unsigned __int128`, `__int128_t` and `__uint128_t` types in the separate GCC 17
WebAssembly output compiler. It follows the eight patches already described in
[README.md](README.md). Exact GCC and patch bytes are pinned in
[sources.lock.json](sources.lock.json).

This document describes the implementation and required qualification matrix.
Completed native/Chromium results, source and asset identities, loading sizes,
and retained failure evidence belong in
[the separate int128 qualification report](../../docs/gcc-wasi-int128.md).
A matrix count or reproduction command here does not declare a bundle verified.

## Representation and code generation

The compiler runs real GCC `cc1`/`cc1plus` frontends and GCC RTL WebAssembly code
generation. Its output goes through the pinned annotated-WAT assembler to a
relocatable Wasm object, then external LLVM `wasm-ld` links the WASI program.
The compiler host is `wasm32-emscripten`; the generated program target is
`wasm32-wasi`, using WASI Preview 1. Emscripten builds the compiler host and
Clang supplies independent native references; neither replaces GCC compilation
of browser-submitted C/C++.

Public int128 uses GCC TImode with 16-byte size and alignment. Values occupy two
little-endian i64 words in locals and linear memory. Enabling the ordinary
scalar-mode hook and a 128-bit `MAX_FIXED_MODE_SIZE` exposes the frontend types,
predefined size macro and GNU library integer specializations. The existing
pair moves and DI/narrow subregister legalization from patch `0008` are reused.
This also lets GCC use TI containers for additional 16-byte aggregate copies,
so previous scalar, aggregate, SIMD and binary128 tests must be rerun.
Floating SF/DF views of a TI/TF pair are legalized through ordinary SI/DI
word pseudos and same-size Wasm reinterpret operations. These preserve the raw
floating bit pattern and the other storage word; they are not numeric
integer/float conversions. Other floating field positions retain GCC
bitfield lowering, and memory moves retain their alignment/volatile attributes.

GCC's generic double-word optabs expand addition, subtraction, bitwise operations,
comparisons and suitable shifts into ordinary word operations. Other operations
use the pinned WASI SDK 33 compiler-rt archive, including signed/unsigned division,
remainder, multiplication and numeric conversions. No new compiler-rt stub or
source translator is supplied. Runtime shift counts explicitly use SImode:
`__ashlti3`, `__ashrti3` and `__lshrti3` take C `int`, although the GCC target's
`word_mode` is DI. Comparison helpers likewise return i32.

A scalar SI/DI complement expander advertises the existing XOR-with-all-ones
operation to GCC's generic TI lowering. This permits a wide complement to split
into word complements instead of calling the unavailable `__one_cmplti2`.
Existing scalar complement already lowers through XOR; this change supplies the
word optab needed by the wider operation.

Int128 does not require SIMD, does not use a `v128` local and does not add a
WebAssembly i128 value type. SIMD-enabled vector parameters retain their
separate, explicit `v128` ABI when mixed with scalar int128.

## Basic C ABI

The implementation follows the
[WebAssembly Basic C ABI](https://github.com/WebAssembly/tool-conventions/blob/25aceba5adba8f3f7cdbadd8e8705784aebcad6a/BasicCABI.md),
pinned here at tool-conventions commit
`25aceba5adba8f3f7cdbadd8e8705784aebcad6a`. Actual WASI SDK 33 Clang 22.1.0
objects independently check the selected convention.

| Value or use | Wasm convention |
| --- | --- |
| Named signed/unsigned int128 | Two i64 parameters, low word then high word |
| Eligible singleton struct/union/nested array wrapper | The same two-i64 argument convention |
| Scalar or singleton int128 result | Leading hidden i32 result pointer; no direct Wasm result |
| Multifield, packed-offset or nontrivial C++ object | Aggregate/invisible-reference rules; memory parameters and result |
| Variadic int128 or a singleton wrapper | Caller argument buffer with natural 16-byte alignment |
| Named int128 mixed with enabled SIMD vectors | Each int128 remains two i64 values; each supported vector is one v128 |

Declarations, definitions, direct calls, imports and indirect-call types share
this classification. The result-pointer convention is preserved for compiler-rt
helpers too. For example, `U multiply(U, U)` and `__multi3` have Wasm type
`(i32, i64, i64, i64, i64) -> ()`; an integer shift helper has type
`(i32, i64, i64, i32) -> ()`. Function-pointer and callback tests check the same
signatures across GCC and Clang translation units.

## Constant initializer defect found during qualification

The first public-int128 native matrix passed 104 of 112 selected non-STL runs
but produced wrong output in eight O0/O2 cases. Division/remainder of unsigned
maximum values, shifts, negative-int128-to-float conversions and storage tests
exposed a common data defect; their Wasm still validated and linked.

`assemble_const_int` used an eight-byte `HOST_WIDE_INT` buffer and passed the
requested 16-byte TI object size to the string serializer. The upper eight bytes
were read past that buffer. Consequently, a global `~(U)0` or a negative value
fitting one host word could contain unrelated upper bytes. Positive small TI
constants in expected-value tables were affected too. Wide constants already
split by GCC into separate word records followed a different path.

Patch `0009` serializes only the available low-word bytes with unsigned shifts,
then emits explicit zero or sign-extension bytes in bounded chunks. It never
reads past the host buffer or shifts by its entire width. The fix covers both
native and 32-bit Wasm compiler hosts. Original failing programs and source/tool
snapshots are retained separately; the corrected compiler must rerun the matrix.
The selected 112-run stage omits four library-dependent controls and cannot
satisfy the complete 116-run packaging gate.

The existing 200-case scalar ABI suite then exposed six GCC-involving failures
at O0/O2 for a 16-byte-aligned struct containing one double. Raising the fixed
integer mode limit let GCC represent that aggregate in a TI container; its
DF subregister reads/writes were not recognized by the existing word cast
patterns. Floating pair-view legalization materializes an ordinary integer
word and a same-size floating pseudo before using the existing reinterpret
patterns. The full scalar ABI suite must pass again before the new compiler
is accepted, independently of the new int128 matrix.

## Reproduce the qualification

Use the exact source/tool setup and native-first build in
[README.md](README.md#reproduction). Rebuild GNU libstdc++ with the current
patched compiler in a fresh directory. Int128 changes predefined macros and
library specializations; an older library receipt is not proof for the new
compiler even when an individual program happens to link.

```sh
export GCC_LIBSTDCXX_WORK_DIR="$GCC_WASI_WORK_DIR/libstdcxx-int128"
bash producer/gcc-wasi/build-libstdcxx.sh
node producer/gcc-wasi/test-libstdcxx.mjs "$GCC_LIBSTDCXX_WORK_DIR/qualification"
node producer/gcc-wasi/test-int128.mjs \
  --work "$GCC_WASI_WORK_DIR" --sdk "$WASI_SDK_PATH" \
  --compiler "$GCC_WASI_WORK_DIR/gcc-native/gcc" \
  --source "$GCC_WASI_WORK_DIR/gcc" \
  --sysroot "$GCC_WASI_WORK_DIR/runtime-c/sysroot" \
  --gcc-cxx-sysroot "$GCC_LIBSTDCXX_WORK_DIR/sysroot" \
  --output "$GCC_WASI_WORK_DIR/int128-qualification"
```

Use the same Node executable for native proof and packaging, which checks its
identity. All output directories must be new. Keep sources, compilers, headers,
runtime archives and test recipes fixed until every consumer finishes. Use
private logs with final exit status for long builds; inspect bounded excerpts
after completion. Rebuild and qualify both GCC compiler hosts from the same
locked source before advertising a new browser bundle.

The [fixture module](int128-fixtures.mjs) has 21 profiles at O0 and O2:
**42 programs**. ABI profiles run GCC/GCC, GCC/Clang, Clang/GCC and Clang/Clang
caller/provider combinations; other profiles run the two same-compiler controls.
The complete native gate requires **116 runs**, including GNU C++ and Clang
library controls. The browser gate compiles all 42 programs with Wasm-host GCC
and executes each in Chromium Worker and independently in Node WASI.

Coverage includes size/alignment, carry/borrow, signed and unsigned arithmetic,
wrapped unsigned multiplication, division/remainder, signed/unsigned comparisons,
shifts at 0/1/31/32/63/64/65/100/126/127, integer/float/double/binary128 conversions,
global/stack/heap/packed storage, loops, calls/function pointers/callbacks,
aggregate and variadic arguments, `va_copy`, mixed SIMD ABI, multiple C/C++ units,
static construction/destruction and GNU numeric_limits/vector/accumulate/sort.
Expected integer values use independent BigInt reference calculations in the
tests; those calculations are outside the compiler path. Every source receives
real `-DONLINE_JUDGE=1` options. Undefined signed overflow, division by zero,
minimum-signed-value divided by -1 and invalid shift counts are excluded.
Negative signed right shift follows the target's arithmetic-shift behavior.

Package only after all current native suites and the fresh GNU runtime pass:

```sh
node producer/gcc-wasi/package.mjs \
  --work "$GCC_WASI_WORK_DIR" --runtime "$GCC_WASI_WORK_DIR/runtime-c" \
  --simd-qualification "$GCC_WASI_WORK_DIR/simd-qualification/qualification.json" \
  --simd-extended-qualification "$GCC_WASI_WORK_DIR/simd-extended-qualification/qualification.json" \
  --vector-abi-qualification "$GCC_WASI_WORK_DIR/vector-abi-qualification/report.json" \
  --long-double-qualification "$GCC_WASI_WORK_DIR/long-double-qualification/report.json" \
  --int128-qualification "$GCC_WASI_WORK_DIR/int128-qualification/report.json" \
  --native-linker "$WASI_SDK_PATH/bin/wasm-ld" \
  --libstdcxx "$GCC_LIBSTDCXX_WORK_DIR" --output out/gcc-wasi-int128-bundle
```

The ninth-patch compiler requires `--int128-qualification` as well as the existing
binary128 proof, native linker and rebuilt GNU runtime. The packager verifies
complete fixture/direction membership, exact source and tool identities, actual
commands and I/O, macro options, headers/runtime archives, objects and linked
programs. It reopens Wasm artifacts and checks types, memory and imports/exports.
A partial or stale report cannot turn on the capability.

From the matching wasm-idle checkout, after building core and GCC packages:

```sh
node scripts/verify-gcc-wasi.mjs \
  --manifest /absolute/path/to/gcc-wasi-int128-bundle/gcc-toolchain.v2.json \
  --suite /absolute/path/to/wasm-llvm/producer/gcc-wasi/int128-fixtures.mjs \
  --save-intermediates --output out/gcc-wasi-int128-browser
```

Saved WAT/object intermediates cover the main translation unit. Executable
compilation includes all requested translation units; mixed-compiler object
linking remains a separate native test. Repeat the existing scalar/SIMD/vector
ABI/binary128 Worker regressions and x86 GCC 13/16 tests with the final SDK.
Record the final bundle's raw/gzip/Brotli sizes and actual browser initial
transfers again; previous bundle measurements do not qualify a rebuild.

## SDK and support boundaries

The optional v2 manifest field `capabilities.int128` is qualification metadata.
An omitted field defaults to false, and false/omitted older manifests retain
their existing compile and link arguments. There is no per-request int128 flag,
source rewriting or extra runtime archive selected by this field. Compiler-rt is
already among the pinned linked libraries. The producer emits
`qualification.status: "unverified"`; the native gate does not substitute for
actual browser compilation/execution or rewrite that manifest afterward.

Int128 support does not enable exceptions, RTTI, threads/TLS/atomics, shared
memory, dynamic linking, relaxed SIMD or arbitrary external binary inputs.
[Patch `0010`](EMPTY-ABI.md) separately repairs the existing empty C++ record
ABI, including `struct alignas(16) Empty {};`, while preserving nontrivial and
ordinary nonzero-size member/array/union controls. GCC/Clang interoperation is
checked through actual linking and execution, beyond GCC-only agreement.

GNU `__float128`, wide atomic interfaces and complete C/C++ conformance remain
outside this matrix. The separate [floating extension profile](FP-EXTENSIONS.md)
covers selected C `_Float128` and GNU complex long-double cases. The additional
[wide builtin and bitfield qualification](WIDE-INTEGER.md) defines source-level
builtin coverage and patch `0011`'s named-field layout and declared-type
singleton ABI repair. Actual `__builtin_clrsbg(__int128)` lowers to word
operations without `__clrsbti2`; that helper's absence does not imply a
source-level failure. Unlisted
target-specific builtins remain unqualified. GNU timezone databases, C++26
debugger functions and prebuilt `std` modules keep their previous exclusions.
x86 AVX2/FMA intrinsics and target pragmas retain their x86-only role.

Corresponding-source and license obligations are unchanged. Distribute the exact
GCC patch series, dependency source identities and complete notices with binary
assets as described in [README.md](README.md#distribution-and-provenance).
