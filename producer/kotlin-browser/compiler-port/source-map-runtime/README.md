# Request-owned source-map runtime

This recipe retains every method in the genuine `SourceMap.kt`, `SourceMapParser.kt`, and `SourceMapLocationRemapper.kt` from Kotlin commit `4d78aae1e337cd40f69baa865aed950fe807a775`. Their immutable originals are supplemental references proved beneath the pinned `js` Git tree. It binds their actual file, reader, writer, print and debug-capture operations to the separately verified request text-IO and AST reader components. JSON parsing, VLQ arithmetic, resolver construction, segment lookup, source replacement and AST visitation algorithms remain intact.

`SourceMapRuntime(files, printOutput)` requires an explicit `SourceMapTextStore` and `SourceMapPrintOutput`. `installRequestSourceMapRuntime(configuration, runtime)` installs the genuine private configuration-key value. `requestSourceMapRuntime(configuration)` retrieves it or rejects a missing installation. A `SourceMap` captures the supplied runtime, so replacing a configuration value does not retarget an existing map. Default debug output uses that captured print destination. This is an explicit request host contract; it does not reproduce changes to JVM global `System.out`, and provides no silent default or global request registry.

The actual source-content-prepared `jsAstUtils.kt` is the one predecessor. Only the contexts of `IrFunction.getJsCode` and its private `parseSourceMap` change from `ErrorReportingContext` to genuine `LoweringContext`, which exposes the compiler configuration. The latter calls the actual parser with the captured request value. The other `ErrorReportingContext` functions remain intact. Three exact incoming callers and six genuine context/type files are pinned. The unrelated Wasm `IrExpression.getJsCode(): String?` is not treated as a call to the JS function parser.

The remapper has one additional Java nullability binding. A default genuine Java `JsFunction` has a null body despite its `@NotNull` getter. The original collector appends the function and visits its parameters before directly dereferencing `getBody().getStatements()`. The common consumer uses a single Elvis boundary at that point, preserving the measured `NullPointerException` message of that selected dereference. This is not a claim of general enhanced-NPE, stacktrace, JVM instrumentation or exception-text parity.

## Preparation and final selection

Call `prepareSourceMapRuntimeReferences()` to fetch and verify the three missing originals, then `prepareSourceMapRuntime({sourceRoot, runtimeSourceRoot, sourceContentComponent, retainedSources, outputRoot})` and `verifySourceMapRuntime` with the returned receipt path. Preparation returns five common sources, three supplemental originals/replacements, one flat predecessor binding, and 121 dependency pins. The predecessor binding records the real filename, bytes, SHA-256 and receipt SHA-256. Shared files belong to the existing AST, JSON, text-IO, configuration and assertion components and must be selected once by the composer.

After import assembly and other selection profiles, call `verifySourceMapRuntimeFinalSources({profileRoot, sourceRoot, runtimeSourceRoot, sourceContentComponent, retainedSources, allowedAddedImports, allowedRequestHostSources})`. It replays the pinned initial caller snapshot and canonical transformations, checks five actual outputs and the other two callers by exact selected path and filename, and compares their bodies after excluding only imports and assembly blank lines. Original imports must remain; only explicitly enumerated added imports are allowed. It scans the actual final selected Kotlin graph and rejects unexpected relevant source-map class/member occurrences. Unrelated `getJsCode` names are not resolved as typed calls. Optional caller-owned entry pins are limited to `compiler-port-entry/BrowserCompiler.kt` and `compiler-port-entry/BrowserCompilerPipeline.kt`; their actual bytes and digest must match the supplied explicit pins. This unit does not modify either entry file or claim that its runtime is installed by the compiler pipeline.
