# KLIB signature index over verified memory

This unit retains the complete selected `KlibSignatureIndexComponent.kt` and
connects its filesystem boundaries to the existing `VerifiedKlibFileSet`,
`LibraryPath`, and `MemoryKlibOutput` contracts. It preserves signature sorting,
string-table construction, protobuf encoding/decoding, current and pre-2.4 IDs,
flags, duplicate elimination, the three-row minimum, and forward-compatible
extra-row handling. Nine exact reversible spans change only the host boundary
and its diagnostic type-name lookup.

Three additional exact spans in the existing generated `MemoryKotlinLibrary.kt`
register the genuine component with `getComponent()`. The component is cached
per library and decodes lazily. An absent index returns `null`; a present invalid
index fails when decoded. A pinned exhaustive mapping of all nine final
`IdSignature` subclasses preserves JVM binary names in invalid-type diagnostics.
The old KLIB and linker source files are not edited.

```js
const component = await prepareKlibSignatureIndex({
  sourceRoot, outputRoot, klibComponent, retainedSources,
});
await verifyKlibSignatureIndex(outputRoot);
const final = await verifyFinalKlibSignatureIndex({
  outputRoot, retainedSources: finalSources, recordedPropertyImports,
});
```

Preparation runs after the KLIB component, before assembly imports. It returns
three sources, one predecessor binding, and two replacement paths. The final
guard checks each exact owner and full body, allowing only recorded assembly
imports. Its `predecessorRetainedSources` restores the old memory-library owner
for a preceding KLIB guard. No source is excluded by this unit.

`sources.lock.json` binds the primary source inventory, complete original index
and sealed signature hierarchy, existing KLIB/linker contracts, recipe, helper,
and generated bytes. `seal.mjs` is an explicit maintainer command; preparation
never rewrites the lock or original sources.

The differential probe compiles the complete original index on JVM and the
complete portable index and memory library on JVM and Wasm, then executes Wasm
in Node. It uses the actual protobuf Java source and the previously verified
portable protobuf artifact, the actual `CommonSignatureSerializer` declaration,
and complete `IrStringSerializer` and `IdSignatureRenderer` sources. Cases cover
empty/import/export/mixed sets, ordering and descriptions, WobblyTF8 strings,
current/legacy/absent IDs, duplicate rows, extra rows, malformed inputs, lazy
component identity, memory writer round trips, and every sealed subtype name.
The recovered actual whole-build selection is also checked before replacing
its two sources and adding the helper.

The dependency proof projects out `IdSignature`'s IR-symbol auxiliary constructor
and unrelated composer interface; all nine signature subclass bodies remain.
Its final-class equality check uses the equivalent common type test. It also
omits an unused `FqNameUnsafe` regex constant and extracts the genuine collection
capacity helper and manifest-layout declaration. These projections are only in
the probe. This is not execution of the entire IR/descriptor dependency closure.
Malformed-input exception details follow the already declared bounded memory
and portable protobuf policies; successful bytes and controlled diagnostics are
compared exactly. Browser execution and the complete browser compiler remain
unverified.
