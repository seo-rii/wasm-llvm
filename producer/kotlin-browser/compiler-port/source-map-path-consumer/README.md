This new recipe retains complete pinned RelativePathCalculator, SourceFilePathResolver, SourceMapBuilderConsumer, SourceMapsInfo, JsCodeOutliningLowering and Wasm SourceMapGenerator sources. Only explicit host/type/caller spans are rebound; unrelated compiler algorithms and all original methods remain.

Diagnostics use the already verified builder's separate banner/throwable operations. No current directory, diagnostic destination or output directory is silently selected, and diagnostics are not closed by this unit.

SourceMapPosixPath is an explicit lexical source-path value outside Java namespaces. Its single-string path construction collapses redundant/trailing slashes; native two-argument POSIX joins and absolute resolution retain the joined spelling, including a trailing slash. Dot normalization is separate and retains Kotlin's colon-root recognition even on Unix. Equality/hash use stable case-sensitive path spelling. Native symlinks, security-manager effects, platform locale, arbitrary File subclasses and Windows filesystem semantics are not supplied by this request host.

The genuine resolver retains unnormalized absolute source roots, the original zip equal-count calculation, identical-path negative-length failure, path cache and parent-directory existence cache. General native File values in JSConfigurationKeys and unrelated compiler output APIs remain a separate boundary. The outlining caller uses its genuine LoweringContext.configuration; the Wasm generator uses its genuine stored CompilerConfiguration. Entry installation remains a separate root-owned integration.

The execution observer rebuilds original algorithms against genuine original AST and pinned fastutil, then builds the actual common AST/builder/resolver/consumer and complete Wasm SourceMapGenerator on JVM and Wasm. The original JsCommonBackendContext extension and full outlining IR class require whole-compiler acceptance and are not replaced by invented models. Original/compiler caller sources remain complete shipping inputs.
