# D browser artifacts

This producer owns the content pins, deterministic toolchain assembly, gzip packaging, runtime
manifest, and receipt previously generated by `wasm-idle/runtimes/wasm-d/scripts/prepare-runtime.mjs`.
`wasm-idle` owns the D runtime API, browser workers, execution, and shared compiler-module cache.

The pinned LDC/DMD/druntime and Phobos WASI patches, frontend probe, llvm-config wrapper,
and finalized-input collection/packaging scripts also live here. They are copied byte for byte
from the recorded `ldc-wasm` commit; `source-port.lock.json` pins all nine recipe files and
`package:d` verifies them before reading compiler inputs. The original checkout is not needed
for these recipes.

```sh
bash producer/d-browser/scripts/apply-ldc-patches.sh /path/to/ldc
pnpm probe:d-frontend -- --ldc-source /path/to/ldc --bootstrap-ldmd2 /path/to/bootstrap/bin/ldmd2
pnpm collect:d-inputs -- --help
pnpm finalize:d-inputs -- --help
pnpm verify:d-inputs -- producer/d-browser/dist/wasm-idle
```

The copied recipes keep their upstream defaults relative to `producer/d-browser` (`build/` and
`dist/wasm-idle`). `verify:d-inputs` resolves its default from the current directory instead, so
pass the finalized directory explicitly.

These upstream porting probes do not constitute a new full compiler rebuild or binary-to-source
attestation. The current migration validates and preserves the finalized compiler bytes.

The accepted input is the finalized `ldc-1.42.0-wasi-smoke` distribution. `sources.lock.json`
pins its source manifest, build metadata, and all seven input files by size and SHA-256. The
`ldc-wasm` recipe commit is recorded in `manifest.json`; it is **not** a verified binary-to-source
build attestation. This command does not rebuild LDC or substitute another compiler.

## Package and verify

Requires Node 20+, GNU tar and zstd. Supply an explicit finalized distribution directory;
the producer does not search sibling repositories or download an unpinned release.

```sh
pnpm package:d -- --source /path/to/ldc-wasm/dist/wasm-idle --out out/d-browser
pnpm verify:d-artifacts -- out/d-browser
pnpm test:d-producer
```

`WASM_LLVM_D_SOURCE_DIR` supplies the same explicit source input. Output directories must be new
and must not overlap inputs. An invalid or interrupted package never replaces an existing output.
All input hashes are checked before archive tools run; only verified snapshots are used. Toolchain
archives may contain regular files and directories, not links or paths outside their root.

The output contains exactly these seven files plus `producer-receipt.json`:

```text
bin/ldc2.wasm.gz
bin/lld.js
bin/lld.wasm.gz
bin/lld.data.gz
toolchain/toolchain.tar.gz
runtime-manifest.v1.json
runtime-build.json
```

The receipt has `schemaVersion: 1`, `format: wasm-llvm-d-browser-artifacts-v1`,
`producerId: wasm-llvm/d-browser`, SHA-256 hashes of the exact producer manifest and source-lock
files, and an `artifacts` array of `{path, bytes, sha256}`. Gzip entries also carry
`uncompressedBytes` and `uncompressedSha256`. Metadata uses a fixed epoch and source identifier;
verification independently reconstructs it from the pinned compiler receipts. The toolchain tar
uses the GNU format with normalized entry order, timestamps, ownership and 0644/0755 modes, so the
caller's umask, `TAR_OPTIONS` and `POSIXLY_CORRECT` do not change it. Gzip delivery hashes may
change with the zlib version; the native and toolchain logical hashes remain pinned, and any
changed delivery receipt requires an explicit consumer lock update.

Consumers must pin the producer receipt itself (or every expected artifact digest), in addition to
its manifest/source-lock identity, and verify all files before publication. A receipt's own hashes
are not an independent trust root. The consumer may map this verified LLD input to its separately
pinned shared Emscripten LLD delivery. Runtime worker generation and application publication remain
consumer responsibilities. No generated binaries are committed by this migration.
